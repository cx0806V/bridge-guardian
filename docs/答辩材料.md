# 桥体卫士 —— 答辩材料包

> 口径红线：本作品是「缩尺桥梁模型受载变化模拟」的完整工程闭环，**不是**经工程级标定的真实桥梁应变监测设备。所有表述以源码、硬件、测试证据为准，不堆砌无法佐证的概念。

## 一、PPT 大纲（建议 10–12 页）

1. **封面**：项目名「桥体卫士」、团队名、成员、日期。
2. **项目背景与痛点**：桥梁结构安全监测的现实需求；现有手段成本高、部署难。
3. **我们的方案**：低成本缩尺模型 + ESP32/HX711 采集 + Web 实时监测的完整闭环。
4. **系统架构**：硬件层 → 采集层（双模式数据源）→ 规则引擎 → 数据层 → 服务层 → 大屏。
5. **双模式数据源**：模拟 / 真实硬件一键切换；设备健康度（心跳 + 超时 + 异常），断线如实离线。
6. **可解释报警引擎**：6 类规则（阈值/变化率/持续超限/短时波动/基线偏移/设备离线），每条报警带原因。
7. **数据可靠性**：统一结构 + SQLite + 审计 + CSV 导出兼容。
8. **安全与工程化**：环境变量密钥、统一鉴权、写接口保护、测试套件、现场手册。
9. **硬件闭环演示**：传感器 → OLED/LED/蜂鸣器本地提示 → 串口 → 大屏 → 处置 → 追溯。
10. **测试与验证**：22 项 pytest 全通过 + 硬件实测截图。
11. **创新点总结**：双模式抽象、可解释规则、设备健康度模型、数据可靠与工程化。
12. **总结与展望**：当前成果 + 后续扩展（HTTP 备份通道、多测点等）。

## 二、讲稿要点（每页 30–60 秒）

- **背景**：桥梁长期受载下结构健康关乎安全，传统监测成本高。我们以缩尺模型模拟受载变化，构建一套可演示、可验证的监测系统。
- **架构**：分层解耦，数据源可插拔。核心是「采集 → 判断 → 存储 → 展示」的闭环。
- **双模式**：现场可用串口直连真实硬件，也可用模拟数据源兜底；设备状态如实呈现，断线即离线。
- **可解释报警**：不只报「超了」，还说明「哪条规则、触发值多少、阈值多少」。
- **可靠性**：统一时间/设备/状态/审计，SQLite 持久化，CSV 可导出。
- **安全**：密钥不硬编码、统一鉴权、写接口受保护。
- **演示**：现场施加载荷，展示从传感器到报警处置的完整链路。

## 三、现场演示流程（约 5 分钟）

1. **登录大屏**：展示风险等级、当前应变值、阈值仪表、实时曲线、设备健康度。
2. **双模式说明**：切换 `.env` 或口头说明 `DATA_SOURCE`，展示设备状态「在线/离线」如实显示。
3. **施加载荷触发报警**：对模型施压，应变值越过阈值，大屏弹出分级报警，OLED/LED/蜂鸣器本地同步提示。
4. **可解释性**：点开报警，展示「规则 + 原因」，说明为何触发。
5. **处置闭环**：点击「确认处理」，状态变为已处理，历史记录同步。
6. **历史追溯**：进入历史页，按时间筛选、统计（均值/最大/最小/超限次数/前后对比）、导出 CSV。
7. **安全说明**：演示未登录访问 API 被拒（401），密钥走环境变量。

## 七、常见评委问题与回答

**Q1：你们的应变值是真实桥梁应变吗？**
A：不是。我们做的是缩尺桥梁模型的「受载变化模拟」，HX711 采集相对变化并转换为相对应变（με），未经过工程级标定。我们如实声明这一口径。

**Q2：为什么用串口（USB），不用 MQTT 或 HTTP？**
A：现场演示最关键是稳定。串口点对点不依赖网络、可离线、可验证（能直接看到字节流），断线状态明确，复杂度最低。MQTT 需要额外 broker，HTTP 依赖路由器，都增加现场不确定性。

**Q3：报警为什么触发？能解释吗？**
A：能。规则引擎内置 6 类规则（含设备离线），每条报警都带「触发规则 + 触发值 + 阈值 + 时间」，大屏和历史页都可见原因。

**Q4：数据存在哪里？会不会丢？**
A：SQLite 持久化（采样、报警、参数、审计、心跳五类表），统一时间/设备/状态字段，支持 CSV 导出。

**Q5：系统安全性如何？**
A：账号密钥走环境变量不硬编码；所有页面与 API 统一鉴权，未登录返回 401；写接口受保护；前端做 XSS 转义。

**Q6：设备断线了怎么办？会不会显示假数据？**
A：设备健康度由心跳时间戳、连续超时计数、最近错误三要素构成，断线立即如实显示「离线」，绝不伪造在线状态或数据。

**Q7：创新在哪里？**
A：双模式数据源抽象、6 类可解释报警规则、设备健康度模型、数据可靠与工程化（SQLite+审计+测试）。每项都有对应源码与测试。

**Q8：规则阈值怎么定的？**
A：阈值、采集周期可在设置页调整（阈值 1–200、周期 0.1–60 秒），规则内部参数（变化率、持续点数、波动/漂移阈值）在 `rules.py` 集中配置，便于讲解与调优。
