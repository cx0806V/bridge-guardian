# 桥体卫士 —— 比赛演示剧本（5–8 分钟）

> 双路径：**路径 A 硬件成功路径**（推荐，最能证明工程闭环）+ **路径 B 硬件故障兜底路径**（切模拟模式，诚实继续）。
> 全程口径：模拟场景明确标注「模拟演示 · 非真实硬件数据」；真实串口模式只展示真实设备数据，绝不伪造。

---

## 路径 A：硬件成功路径（约 6 分钟）

| 时间 | 环节 | 操作 | 讲解要点（口语） |
|---|---|---|---|
| 0:00 | 开场 | 大屏已就绪，绿色「安全」 | 「桥体卫士，一个桥梁受载监测的缩尺原型。现在是真实硬件模式，数据来自 ESP32 串口直连。」 |
| 0:30 | 硬件受载 | 对缩尺模型施压/放砝码 | 「我给模型施加一个载荷，注意看大屏的应变指标在上升。」 |
| 1:00 | 本地声光 | 蜂鸣器响、红灯亮、OLED 显示 ALARM | 「这是硬件本地报警，即使电脑没开也会响，双重保障。」 |
| 1:20 | Web 报警 | 大屏弹出报警条目（含规则+原因） | 「Web 端同步报警，每条都写清『哪条规则、触发值多少、阈值多少』。」 |
| 1:40 | 分级展示 | 说明预警/报警/严重报警三级 | 「超过阈值是预警，1.1 倍是报警，1.2 倍是严重报警，分级明确。」 |
| 2:00 | 处置闭环 | 点击「确认处理」 | 「点确认，状态变已处理，形成处置闭环。」 |
| 2:20 | 历史追溯 | 切历史页看时间线+统计+导出 | 「历史页有风险时间线、统计摘要，可导出 CSV。」 |
| 2:50 | 设备健康度 | 指设备健康度卡片 | 「设备健康度由心跳、超时计数、最近错误三要素构成。」 |
| 3:20 | 离线演示 | 拔掉 USB（或给 ESP32 断电） | 「我拔掉设备，大屏会如实显示『设备离线』，并触发『设备离线』严重报警，绝不沿用旧值假装在线。」 |
| 3:50 | 恢复 | 重新上电 | 「重新连接，系统自动记录『设备恢复』。」 |
| 4:10 | 工程化收尾 | 指测试/审计 | 「我们有 37 项自动化测试全绿、全程审计、故障注入脚本 6/6 通过。」 |
| 4:40 | 总结 | 讲创新点+边界 | 「完整闭环、可解释、可追溯、不造假。同时诚实说明：这是缩尺模型受载模拟，不是工程级桥梁标定。」 |

---

## 路径 B：硬件故障兜底路径（切模拟模式，约 5 分钟）

**触发条件**：现场硬件突发故障（ESP32 连不上、传感器无读数、串口乱码无法恢复）。

**切换步骤**（约 30 秒，诚实切换，不硬撑）：
1. 口头说明：「现场硬件出了点状况，为了不耽误演示，我切到系统自带的模拟模式继续，模拟数据会在界面明确标注，不会伪装成真实数据。」
2. 重启服务：`.env` 改 `DATA_SOURCE=sim`，`python app.py`（或启动前就用模拟模式备用）。
3. 大屏顶部出现**「模拟演示 · 非真实硬件数据」水印** + 场景切换面板。

**模拟场景演示流程**（一键复现，可审计）：

| 环节 | 操作（点击场景按钮） | 预期表现 |
|---|---|---|
| 正常运行 | 「正常运行」 | 应变指标围绕 80 小幅波动，绿色安全 |
| 预警 | 「预警」 | 指标稳在 108~115，接近阈值但未越线 |
| 报警 | 「报警」 | 指标稳在 132~140，触发「阈值超限」报警 |
| 严重报警 | 「严重报警」 | 指标稳在 148~160，触发严重报警 |
| 设备离线 | 「设备离线」 | 如实显示「模拟离线」，无新数据，不伪造 |
| 设备恢复 | 「设备恢复」 | 回到正常运行，记录恢复 |

**兜底路径讲解要点**：
- 「模拟模式是系统内置的测试与兜底能力，每个场景一键复现、写入审计，界面明确标注模拟，不伪装真实硬件。」
- 「这恰恰说明系统的双模式设计——即使硬件出问题，也能完整演示采集→判断→存储→处置的闭环。」

---

## 切换模式操作速查

| 模式 | .env 配置 | 界面标识 |
|---|---|---|
| 真实串口 | `DATA_SOURCE=serial` + `SERIAL_PORT=COM3` | 「数据源：串口(真实)」，无水印 |
| 模拟 | `DATA_SOURCE=sim` | 「数据源：模拟」+「模拟演示·非真实硬件数据」水印 + 场景面板 |

> 注意：`/api/scenario` 在串口模式下会拒绝切换（返回错误），这是刻意的诚实边界——真实模式不允许伪造场景数据。
