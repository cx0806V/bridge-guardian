## 2. 第 1 步 · 电脑侧准备（约 10 分钟）

### 2.1 装 CH340 驱动（关键，先做）

1. 用第 1 件数据线把 ESP32 插到电脑 USB 口（此时**先不接任何模块**，降低误判）。
2. 打开设备管理器（`Win+X` → 设备管理器），看「端口 (COM 和 LPT)」：
   - 出现 `USB-SERIAL CH340 (COMx)` → 驱动已就绪，记下 **COMx**（后面所有命令都要用它）。
   - 没有该分类，或「其他设备」下有带黄色感叹号的 `USB2.0-Serial` / `未知设备` → 去 WCH 官网下载 **CH341SER** 驱动安装后重新插拔：<https://www.wch.cn/downloads/CH341SER_EXE.html>
     （Win10/11 有时会经 Windows Update 自动装好，先等 1 分钟再装驱动。）
3. 命令复核（比肉眼看设备管理器更硬）：

```powershell
python -m serial.tools.list_ports -v
```

期望输出形如 `COM3` + `USB-SERIAL CH340`。**若输出 `no ports found`**，按顺序排查：换一条数据线 → 换一个 USB 口（优先主板后置口，不用 USB Hub）→ 装 CH341SER → 换电脑试。
> 本次自我检索时（2026-09-30）本机 `no ports found`（一个 COM 口都没有），说明这块板当时还没插上或驱动未装，属正常。

## 3. 第 2 步 · 断电压接线（约 15 分钟）

### 3.0 铁律

- **先拔掉 USB**，接线全程断电；接完自查再看第 4 节，最后才上电。
- **HX711 的 VCC 接 3V3，不要接 5V**：HX711 用 5V 供电时 DT 输出会变成 5V 电平，ESP32 引脚不耐 5V，可能损伤。
- **所有 GND 必须共地**（ESP32、HX711、OLED、蜂鸣器、LED 模块的地接到同一条 GND 轨）。

### 3.1 接线表（与 `firmware/main.py` 顶部常量一一对应）

**ESP32 → HX711（称重采集）**

| ESP32 丝印 | 接到 | 说明 |
|---|---|---|
| `GPIO21` | HX711 `DT`（有的板标 `DOUT`） | 数据线 |
| `GPIO22` | HX711 `SCK`（有的板标 `CLK`） | 时钟线 |
| `3V3` | HX711 `VCC` | **不要接 5V**（见 3.0） |
| `GND` | HX711 `GND` | 共地 |

**HX711 → 1 kg 圆称（四线，典型色序）**

| HX711 端子 | 圆称线色（典型） | 含义 |
|---|---|---|
| `E+` | 红 | 激励正 |
| `E-` | 黑 | 激励负 |
| `A+` | 绿 | 信号正 |
| `A-` | 白 | 信号负 |

> **色序必须以第 3.3 节的实测为准**：不同厂家线色不统一，接错不会烧，但读数会反或不动。

**ESP32 → OLED 0.96"（4 针 I2C）**

| ESP32 丝印 | OLED 丝印 | 说明 |
|---|---|---|
| `3V3` | `VCC` | 供电 |
| `GND` | `GND` | 共地 |
| `GPIO5` | `SCL` | I2C 时钟（ESP32 默认 I2C 脚之一） |
| `GPIO4` | `SDA` | I2C 数据（ESP32 默认 I2C 脚之一） |

**ESP32 → 蜂鸣器模块 / LED 模块**

| ESP32 丝印 | 模块丝印 | 说明 |
|---|---|---|
| `GPIO26` | 蜂鸣器 `I/O`（或 `S`/`IN`） | 高电平响（与固件 `buzzer.value(1)` 一致） |
| `3V3` / `GND` | 蜂鸣器 `VCC` / `GND` | 模块供电 |
| `GPIO27` | 红灯模块 `S`（或 `IN`） | 报警指示 |
| `GPIO14` | 绿灯模块 `S`（或 `IN`） | 正常指示 |
| `3V3` / `GND` | 两个 LED 模块的 `+` / `-` | **模块自带限流电阻，不再外接电阻** |

> 两个提醒：
> ① 电子积木模块的针序有的印 `- + S`，有的印 `S + -`，**按丝印接，不要按位置接**；上电前用第 4 节的方法单独验一次极性。
> ② `GPIO4`/`GPIO5` 同时是 ESP32 的 strapping 脚，但它们是官方默认 I2C 组合，接 I2C 器件（空闲为高电平）不影响启动；本方案用到的 7 个脚（4/5/14/21/22/26/27）在 30Pin 与 38Pin 版 ESP32 开发板上都存在，对照板上丝印即可。

### 3.2 供电与地

- 整条面包板导轨由 **ESP32 的 `3V3`** 供给（USB 供电，够 HX711 + OLED + 蜂鸣器 + 2 只 LED 用）。
- MB102 电源模块本次**不接**：它需要外部 6.5–12 V DC 或独立 USB 供电，接上反而容易和 USB 形成双电源倒灌。
- 导轨做法：ESP32 `3V3` → 面包板红轨；ESP32 `GND` → 面包板蓝轨；所有模块从红/蓝轨取电。

### 3.3 圆称四线判定（万用表，约 5 分钟；没有万用表就按典型色序接，见下方兜底）

1. 万用表打 **Ω 档**，四根线两两测：能测到约 1 kΩ 的两根是一组。
2. 你会得到**两组**：一组是激励（E+/E-），一组是信号（A+/A-）。交叉测（E 组任一线对 A 组任一线）阻值约为两组之和（≈2 kΩ）——若某根线与其它三根都不通，说明内部断线，直接联系换货。
3. 哪组是激励？**1 kg 圆称的常见经验值：输入(激励)阻抗 ≈1090 Ω，输出(信号)阻抗 ≈1000 Ω，即阻值略大的那组是 E+/E-**。这是经验判据，不是绝对规则（不同批次可能接近），最终以第 7 节「加载后读数变大」为准。
4. **接线不会烧器件**：
   - 加载后读数**变小** → 把 `A+` 与 `A-` 对调即可（只改变符号方向）。
   - 读数完全不动 / 一直超时 → 多半是 E 组与 A 组接反，或 DT/SCK 没接好。
5. 兜底（无万用表）：先按红=E+、黑=E-、绿=A+、白=A- 接，上电看第 7 节输出；若读数反向就对调绿白。

### 3.4 传感器安装（支架散件）

- 圆称分**固定端**与**受力端**（按传感器表面箭头/丝印判断，箭头指向受力方向）：固定端用随机 M4 螺丝拧死到底座，受力端装托盘/平台。
- **托盘不得与底座、桌面或其它物体接触**（一接触就会出现零点漂移、读数不回落）。
- 引出线用扎带固定在支架上，别让线材拉力直接作用在传感器上。
- 加载位置每次一致（砝码放托盘中心）——这是重复性（同档两次加载差值）的前提。

### 3.5 接完自查（6 条，逐条打勾）

- [ ] HX711 `VCC` 在 `3V3` 轨上，**不在 5V 轨**
- [ ] 所有模块 `GND` 与 ESP32 `GND` 连通（万用表通断档确认一遍）
- [ ] HX711 `DT→GPIO21`、`SCK→GPIO22`，没有插到相邻孔
- [ ] OLED `SCL→GPIO5`、`SDA→GPIO4`（SCL/SDA 别对调）
- [ ] 红/绿灯模块 `S` 分别接 `GPIO27`/`GPIO14`，`+`/`-` 接对
- [ ] 蜂鸣器模块 `I/O` 接 `GPIO26`

## 4. 第 3 步 · 上电前自检：模块极性（1 分钟）

固件默认 **高电平点亮/发声**。接上 USB 后如果发现灯是"反的"（正常时红灯亮），先做这个一分钟验证：

1. 拔下模块的 `S` 针，用一根跳线把 `S` 端**短暂接到 3V3** → 灯亮/蜂鸣器响 = 高电平触发（与固件一致，正常）；
2. 若接 3V3 不亮、接 GND 才亮 = **低电平触发模块**（少数批次或发错货）：
   - 处理 A（推荐）：把该模块换成套装里对应的另一只（蜂鸣器有 2 只可换）；
   - 处理 B：改固件把该脚的 `1/0` 取反（只改对应 `Pin.value(...)` 调用，逻辑语义不变，需在代码注释里写明"低电平触发模块"）。
3. 绿 LED 接 `GPIO14`：ESP32 上电/复位瞬间该脚可能有极短脉冲（属正常现象），不影响状态判读。

> `micropython/drivers/display/ssd1306/ssd1306.py`。

> 没有 OLED、或驱动缺失也不会崩：`main.py` 里 OLED 初始化包在 `try/except` 中，失败时 `oled=None`，自动降级只用串口 + LED/蜂鸣器。

## 7. 第 6 步 · 空载自检（约 3 分钟）

### 7.1 看输出

```powershell
python scripts/calib_log.py --port COM3 --tag 空载 --count 5
```

工具会打印 CSV 并在结束时给出该档的 raw 平均值/标准差（直接填进标定表）。
期望每行形如（字段与 `datasource.SerialSource` 解析口径一致）：

```
空载,1,2026-09-30 21:03:28,8300100,-0.35,uncalibrated,0,0,1,ESP32-01
  tag   idx  iso_time          raw_value calibrated_value 状态  错误码 标定版本 seq 设备号
```

对应固件实际输出的一行 JSON：

```json
{"schema_version": 2, "seq": 1, "device_ts": 1790773000, "raw_value": 8300100,
 "calibrated_value": -0.35, "unit": "相对应变指标", "calibration_version": 0,
 "sensor_state": "uncalibrated", "error_code": 0, "id": "ESP32-01"}
```

### 7.2 判断

| 现象 | 含义 | 处置 |
|---|---|---|
| `raw_value` 有数、小幅跳动（几十~几百计数） | 正常 | 进入标定 |
| `sensor_state=uncalibrated`、`calibration_version=0` | 尚未标定（设计如此，仍输出读数供标定用） | 第 7 节标定后消失 |
| 全是 `sensor_state=fault`、`error_code=1` | HX711 无响应 | 查 `DT/SCK` 接线、HX711 供电、3.3 V 是否到位 |
| `error_code=2` | 连续异常超阈值（`CONSECUTIVE_ERROR_LIMIT=5`） | 同上，先修物理连接 |
| `raw_value=0` 恒定不动 | DT 未接或接错孔 / 传感器未接 | 复查 3.1 与 3.3 |
| 读数巨大且满量程乱跳 | E 组与 A 组接错 | 按 3.3 重判四线 |

**采样节奏**：固件每轮要读 8 次 HX711（默认 10 SPS ≈ 0.7 s）再 `sleep(1.0)`，**推算约 1.7 s 输出一行**，不是严格 1 Hz —— 现场以实测间隔为准，并记进标定表「采样周期」行。
**终端乱码**：中文标签在部分 Windows 控制台可能显示为乱码，属显示问题；`--csv` 落盘文件是 UTF-8，用 Excel/WPS 打开正常。

## 8. 第 7 步 · 标定（约 20 分钟，只做一次，重标要升版本号）

完整可复现流程与记录表见 `docs/标定与实测记录模板.md`；下面是动手顺序。

### 8.1 前置

- [ ] 传感器已固定、托盘不接触任何物体，**预热 ≥5 分钟**
- [ ] 无风、无震动、桌面稳定
- [ ] 砝码就位（200 g 套装，常见 200/100/50/20/10/5 g，按实际到货核对）

### 8.2 空载标零点

```powershell
python scripts/calib_log.py --port COM3 --tag 空载 --count 5 --csv .workbuddy\calib\calib.csv
```

等读数稳定（连续 30 秒波动 < ±2 个 raw 计数）后记录，取工具输出的 **raw 平均** 作 `OFFSET`。

### 8.3 分档加载

四档（≥3 档即可，用组合凑档）：

| 档位 | 载荷 | 怎么凑（200 g 套装） |
|---|---|---|
| L1 | 50 g | 50 g |
| L2 | 100 g | 100 g |
| L3 | 150 g | 100 + 50 g |
| L4 | 200 g | 200 g |

每档：放稳 → 等 5 秒 → 连续记 5 次（够工具跑约 10 秒）：

```powershell
python scripts/calib_log.py --port COM3 --tag L2_100g --count 5 --csv .workbuddy\calib\calib.csv
```

每档做完**卸回空载**，确认读数回落到零点附近（判断迟滞/漂移），再做下一档。

### 8.4 算 `SCALE` / `OFFSET`

用纯标准库最小二乘（把 `raw` 换成你四档的实测平均）：

```powershell
python -c "load=[0,50,100,150,200]; raw=[0,0,0,0,0]; n=len(load); mx=sum(load)/n; my=sum(raw)/n; a=sum((x-mx)*(y-my) for x,y in zip(load,raw))/sum((x-mx)**2 for x in load); b=my-a*mx; sst=sum((y-my)**2 for y in raw); ssr=sum((y-(a*x+b))**2 for x,y in zip(load,raw)); print('SCALE=%.3f  OFFSET=%.1f  R2=%.4f'%(a,b,1-ssr/sst))"
```

- `SCALE = a`（每个克数对应的 raw 计数），`OFFSET = b`（拟合截距）。
- **判据：`R² ≥ 0.95`**；低于 0.95 说明安装/加载有问题（托盘接触、砝码位置不一致、传感器未固定牢），排查后重测，不要凑数。
- 若 `b` 与空载实测平均差得远（超过空载标准差 3 倍以上），说明存在预载或迟滞：先查安装，再决定 `OFFSET` 取空载实测值还是拟合截距，并把两个数都记进标定表。

### 8.5 回填固件并升版本

1. 改 `firmware/main.py`：`OFFSET`、`SCALE` 填实测值，`CALIBRATION_VERSION` **+1**（从 0 改到 1）。保存。
2. 重新上传并复位：

```powershell
python -m mpremote connect COM3 fs cp firmware/main.py :main.py
python -m mpremote connect COM3 reset
```

3. 复测：`sensor_state` 应变成 `ok`、`calibration_version=1`，读数随载荷**单调、稳定**变化。

### 8.6 口径说明（答辩时会被问到）

按上面的取法，**指标数值恰好≈施加的克数**（`(raw−OFFSET)/SCALE = 载荷克数`），这让阈值 120 有了直白含义：**约 120 g 越线**。对外口径仍是"**相对应变指标（无量纲）**"，**不说微应变、不说工程级标定**。
（若想让指标变成"满量程百分比"，把 `SCALE` 改成 200 g 对应的 raw 变化量即可让 200 g → 100；但那样默认阈值 120 永不触发，必须同步下调 `THRESHOLD`。不建议现场临时改。）

## 10. 第 9 步 · 端到端验收（约 10 分钟，现场必做）

### 10.1 分级报警复现表（阈值默认 120，标定口径 A）

| 加载 | 指标≈ | 预期分级 | 规则依据（`rules.py::_level`） |
|---|---|---|---|
| 0 g | 0 | 安全 | — |
| 50 g | 50 | 安全 | < 120 |
| 100 g | 100 | 安全 | < 120 |
| **125 g**（100+20+5） | ~125 | **预警** | 120 < v < 132 |
| **135 g**（100+20+10+5） | ~135 | **报警** | 132 ≤ v < 144 |
| **150 g**（100+50） | ~150 | **严重报警** | v ≥ 144 |
| 200 g | ~200 | 严重报警 | v ≥ 144 |

### 10.2 会被触发、且必须能解释的"额外报警"（不是 bug）

| 规则 | 触发条件 | 现场什么时候会看到 |
|---|---|---|
| **变化率突变** | 单周期 \|Δ\| ≥ 10（≥20 判严重报警） | **每次放/拿砝码的瞬间**都会触发一次（Δ≈载荷克数） |
| 持续超限 | 连续 5 个采样点超阈（≈8–9 s） | 150 g/200 g 保持约 10 秒后 |
| 短时波动 | 10 点窗口峰谷差 ≥ 30 | 快速加-卸载（约 17 s 内完成一次加一次卸） |
| 基线偏移 | 30 点窗口近期均值相对基线偏移 ≥ 20 | 持续加载约 50 s 后 |

> 答辩要点：这些是**可解释规则**的设计结果（每条报警都带「触发规则 + 触发值 + 原因」），
> 说明系统区分"瞬时冲击""持续超限""漂移"三类工况，而不是只做简单阈值比较。

### 10.3 验收清单（逐条打勾）

- [ ] 空载：`/device` 设备在线，心跳刷新；大屏指标接近 0
- [ ] 100 g：指标≈100，**安全**（不报警）
- [ ] 135 g：进入**报警**，蜂鸣器响一声、红灯亮、绿灯灭（固件超 `THRESHOLD` 即本地提示）
- [ ] 150 g：**严重报警**，报警队列出现条目，带规则名与触发值
- [ ] 处置闭环：在大屏/报警页点「确认处理」→ 状态变更并写审计（`/settings` 最近变更可查）
- [ ] **拔掉 USB**：约 5 s 内（代码推算 10 × `read_timeout` 0.5 s）`/device` 变「设备离线」，触发「设备离线」**严重报警**，且**不沿用旧值**
- [ ] **重新插上 USB**：自动记录「设备恢复」（预警级），心跳恢复刷新
- [ ] 历史：`/history` 能看到本次采样与报警记录，CSV 可导出
- [ ] 全程顶栏**无**「模拟演示」徽章（真实模式不得伪装）

## 12. 故障速查表

| 现象 | 定位 | 处置 |
|---|---|---|
| `no ports found` / 设备管理器无端口 | 数据线是纯充电线 / CH340 驱动缺失 / USB 口坏 | 换数据线 → 装 CH341SER → 换口（不用 Hub） |
| 设备管理器黄色感叹号 `USB2.0-Serial` | CH340 驱动未装 | 安装 CH341SER 后重新插拔 |
| `esptool` 报 `Failed to connect` | 没进下载模式 / 端口错 | 按住 BOOT → 点 EN → 松 BOOT；核对 `--port` |
| `esptool` 报 `could not open port ... Access is denied` | 串口被占用（Thonny/监视器/app.py/mpremote） | 关掉占用程序，一次只留一个 |
| 烧录后无任何输出 | 偏移写错（ESP32 是 `0x1000`）/ 固件不匹配 | 重新 `erase-flash` 后按 `write-flash -z 0x1000` 再写 |
| 串口全是乱码 | 波特率不是 115200 / flash 残留旧固件 | 核对 `SERIAL_BAUD=115200`；重刷固件 |
| `sensor_state=fault, error_code=1` | HX711 无响应 | 查 DT/SCK、3V3、共地 |
| 读数恒定 0 或不动 | DT 插错孔 / 传感器未接 / E 组接错 | 复查 3.1、3.3 |
| 加载后读数变小 | A+/A- 反了 | 对调绿白两根 |
| 零点持续漂移 | 托盘接触物体 / 预载没卸净 / 未预热 | 按 3.4 重装，预热 5 分钟再标 |
| OLED 不亮 | I2C 接错或驱动缺失 | 查 SDA=GPIO4 / SCL=GPIO5；确认已上传 `ssd1306.py`（不接 OLED 不影响主流程） |
| 蜂鸣器常响 | 模块为低电平触发 / `I/O` 接到 3V3 | 按第 4 节验极性，换模块或反相改固件 |
| 大屏「设备离线」但板子在跑 | `SERIAL_PORT` 写错 / 串口被占 | 核对端口号；关闭占用程序后重启 `app.py` |
| 登录失败 | `.env` 里账号密码 | 核对 `APP_USERNAME` / `APP_PASSWORD` |
