# P2 交付：3D 帧率优化 + 3D 浅色渲染 + 全屏 BUG 修复

> **可配置目标帧率 + 自适应画质阶梯 + 增量着色 + 浅色天光渲染**，并修掉用户反馈的
> 「手机端/电脑端全屏后显示很奇怪」。
>
> 本文件里的每一个数字都来自脚本实测，测量脚本与原始日志都在 `.workbuddy/p2/` 下，可一键复跑。
> **无法实测的项目一律标注「未实测，依据代码分析」**，不编造。

## 1. 实测前提（口径先讲清楚）

| 项 | 值 |
|---|---|
| 机器 | 本机 Windows，**无独立显卡可用测试通道** |
| 浏览器 | Microsoft Edge 154.0.4258.37（headless） |
| WebGL | ANGLE (Google, Vulkan 1.3.0 SwiftShader Device (Subzero)) —— **纯软件光栅化** |
| 测量工具 | `.workbuddy/p2/measure.py`（改前 `before_measure.json`，改后 `after_*.json`）、`lead/check_fs_layout.py`、`lead/check_integration.py`、`perf-core/tier_bench.py` |
| 视口 | 2560×1600（DSF 1）、390×844（DSF 2，手机竖屏）、844×390（DSF 2，手机横屏）、1024×768（DSF 2，平板） |
| 串行纪律 | 所有浏览器实测通过 `.workbuddy/p2/blocklock.py`（FIFO 票据队列）串行，避免多个软件渲染浏览器互相拖慢 |

**三条口径声明（很重要，别误读）：**

1. **本机的 fps 不代表真机**。SwiftShader 下 2320×1490×MSAA4 ≈ 1380 万采样的单帧光栅成本约
   1058ms（`render()` 之后立刻 `gl.readPixels(1×1)` 强制同步测得）。真机 fps 请用 `/static/perf.html` 回填。
2. **`renderer.render` 次数/秒不可跨版本比较**：改前它是「`×0.7` 限帧 + 1/3 抽帧」下的*提交*计数
   （8.16 次/秒，与真实出帧无关）；改后它受真实光栅背压约束（0.91 次/秒）。两者口径不同，
   **不写进「fps 改前→改后」对比表**，避免把口径差异误读成性能回退。
3. **跨版本可比的是硬件无关计数**：draw calls / 三角形数 / 顶点数 / 几何体数 / program 数 /
   画布后备像素 / MSAA 采样数 / 吊索颜色上传次数。本机唯一可比的 fps 类证据是
   **强制完成口径**（readPixels 强制同步），且只用于**档位之间**的相对收益。

## 4. 全屏 BUG：根因与修复（四个视口实测）

根因：`body.view-3d-only` 用 `visibility` 隐藏顶栏/侧栏/指标带/模拟条 —— **元素仍然占位**，
而 `.hero` 被写成 `100vh` 且 `body{overflow:hidden}`。实测：

| 视口 | 改前症状（实测矩形） | 改后（实测矩形） |
|---|---|---|
| 2560×1600 | `.hero`=(240,62,2320×**1600**) → 底边 1662 > 视口；工具条 y=1589 被裁；左侧 240px 白带 | `.hero`=**(0,0,2560×1600)**；工具条 y=1527..1586 完整；无重叠 |
| 390×844 | `.hero`=(0,156,390×672)、画布只有 388px（46vh） | `.hero`=**(0,0,390×844)**、画布 390×844 |
| 844×390 | `.twin-stage`=320px 而 hero=390px → 底部 70px 空带；侧栏占 64px 宽 | `.hero`=**(0,0,844×390)**、stage=844×390、侧栏零占位 |
| 1024×768 | 状态条与工具条重叠 374×20 | **(0,0,1024×768)**、无重叠 |

另修：手机竖屏全屏下 `.scene-label` 因 app.css 的 `labelIn` 动画压过静态 transform 而跑到 x=-94
（半个标签在屏幕外）→ 加 `animation:none !important` 后 x=10；状态条与跨中读数重叠 208×23 → 状态条改贴底左锚；
状态条与性能角标重叠 164×23 → 状态条左锚 + 角标右锚，手机全屏展开态 `bottom:128px`。
证据：`.workbuddy/p2/logs/fs1..fs5_layout.json`、报告 `.workbuddy/p2/reports/lead-fullscreen.md`。

### 5.2 本机强制完成口径（唯一可比的 fps 类证据，仅档位间比较）

协议：`setActive(false)` 停主循环 → `applyPreset('full', true)` 固定机位 → 逐档 `setQualityTier()`
→ 等 1.8s 落定 → `render()` 后立刻 `gl.readPixels(1×1)` 强制同步，测真实出帧耗时。
脚本 `python .workbuddy/p2/perf-core/tier_bench.py`，JSON `.workbuddy/p2/logs/after_perfcore_tierbench.json`。

| 档位 | 像素比 | MSAA | 雾气/流光 | 地形顶点 | draw calls | 三角形 | 中位帧耗时 | 强制 fps | 相对高档 |
|---|---|---|---|---|---|---|---|---|---|
| 高 | 1（dpr=1 未生效） | 4 | 开 / 6 | 33,371 | 129 | 123,872 | 1069.0 ms | 0.94 | 1.00× |
| 中 | 1（同上，档位上限 1.2 未生效） | 4 | 开 / 6 | 33,371 | 129 | 123,872 | 1074.6 ms | 0.93 | 0.99×（噪声） |
| 低 | 1 | **0** | 关 / 0 | 33,371 | **115** | 119,824 | 502.1 ms | 1.99 | **2.13×** |
| 极低 | 1 | 0 | 关 / 0 | **8,436** | 115 | **70,324** | 428.2 ms | 2.34 | **2.50×** |

- **高档 → 极低档：帧耗时 1069ms → 428ms（−60%）**。本机 `dpr=1`，所以档位像素比上限（1.5/1.2）都不生效，
  收益全部来自「关 MSAA + 关迷雾/流光 + 降地形密度」；真机 dpr 2~3 上还会叠加像素比档的像素量收益
  （1.5→1.2 ≈ −36%、手机 1.4→1.2 ≈ −27%），**这一句是推算，不是实测**。
- 低档第一次采样 2964.8ms 是**换档落定的一次性尖峰**（重建 renderer + 新 context + 首帧着色器重编译），
  稳态 467~525ms。它对应「自动降档瞬间会卡一下、之后立刻变快」，如实记录不掩盖。
- 4 条 `GPU stall due to ReadPixels` 是**诊断脚本自己 readPixels 造成的**性能警告，不是产品告警
  （常规自测与生产路径 0 error / 0 warning）。

### 7.7 已知残留（不影响 P2 验收，如实记录）

1. **隐藏后台时的 ≤1 帧边界效应**：合成 hidden 后 2.5s 窗口内 `perf.renders` 增量实测 0（桌面）/1（手机）；
   `state.running=false`、rAF 已 cancel、interval 已 clear —— 那 1 帧是 `stop()` 与「已在执行/已排队的一帧」
   的边界效应（≈0.4 帧/秒，不是持续渲染）。需求「完全停止渲染循环」已满足，数值边界如实记录。
2. **手机端详情卡展开时会盖住画布中部**（perf-core 自测插桩发现）：卡片是用户点选后才出现的可关闭浮层
   （自带「收起」），属设计内行为；若后续要让「卡片不挡后续交互」，建议在 hud.js 里做「点击卡外即收起」，
   列入 P3 体验项。
3. 低档关闭雾气后谷底「云海」多层叠加的层次感消失（纵深由 FogExp2 承担）；想要云海请手动选高档。
4. 两条已写好但未实测效果的调优旋钮：水面压暗（`water.roughness 0.15→0.25`、envIntensity 1.05→0.9）、
   钢构再压暗（`#5b646c→#4b545c`）——需要时改一行再跑一次三视口统计即可。

**已知残留 / 未实测项（如实列出）**

1. 真机 fps、真机全屏手势（iOS Safari 无 element fullscreen）、刘海屏安全区、真实高刷屏行为：**未实测**，

5. P3 预留接点（节点级告警）：

   - 线框/描边：`theme.js` 已把线框参数（颜色/不透明度/混合模式）参数化，节点告警描边可直接复用；
